# video-pacing

[![CI](https://github.com/kennywu411-dev/video-pacing/actions/workflows/ci.yml/badge.svg)](https://github.com/kennywu411-dev/video-pacing/actions/workflows/ci.yml)

检查一条短视频的节奏：前 5 秒有没有给人留下来的理由，之后每隔几秒有没有新东西。

它是一个 Agent skill（给 Claude Code 这类编程助手用），加一个只依赖 ffmpeg 的 Python 脚本。脚本负责量，助手负责看图和下结论。脚本也可以单独用。

![开头 6 帧：0 到 5 秒，每秒一帧](examples/hook.jpg)

上图是脚本存下来的开头 6 帧（0、1、2、3、4、5 秒），出自我自己的视频《假如你是一滴水》。

## 为什么做这个

我做科普短视频，给自己定了三条规则：

| | 规则 |
|---|---|
| 开头 | 5 秒内画面上要有一个让人留下来的理由，第 0 帧就要有主体、有字 |
| 节奏 | 每 1.5 到 3 秒有一次新东西 |
| 等待 | 不能连续 3 秒以上没有新东西 |

“新东西”指观众能读到或看到之前没有的内容：新一句字幕、新的物体或标签、读数跳到新值、揭晓、切镜头、换景别。飘动、呼吸、粒子、循环动画、镜头慢推都不算，动不等于有信息。

规则确定之后，检查仍然依赖抽帧和主观判断。有一条视频完成后观感偏慢，把字幕起点和镜头切点列成表后发现，有十几段超过 3 秒没有新信息。这项检查每条视频都要做，因此写成了脚本。

## 安装

需要 Python 3.10 以上和 ffmpeg。

作为 skill 装到 Claude Code：

```bash
git clone https://github.com/kennywu411-dev/video-pacing ~/.claude/skills/video-pacing
```

之后说“帮我检查这条视频的节奏”就会用到它。只想用脚本的话，克隆到哪里都行。

## 用法

```bash
python3 scripts/pacing.py 视频.mp4 --out 输出目录
```

两分钟的 1080p 视频大约 10 到 20 秒跑完。输出目录里有：

- `report.md`：开头、节奏、每一段等待的起止时间。样例见 [examples/report.md](examples/report.md)
- `hook.jpg`：开头 6 帧
- `gap_*.jpg`：每一段等待内部的几帧，用来确认这段时间里是不是真的没有新东西
- `pacing.json`：全部数字

下面是一段被标出来的等待（5 秒），三帧分别取自它的开头、中间和结尾。字幕没换，只有镜头在推。这一段是给观众留的答题时间，属于故意的停顿，脚本分不出来，要人来判断。

![一段等待内部的三帧](examples/wait.jpg)

还没渲染的时候，可以先查分镜。把每句字幕、每个镜头切点、每个画面事件的时间列出来：

```bash
python3 scripts/pacing.py --beats 0,1.5,4.2,6.0,11 --duration 14
```

其他参数：`--max-gap` 改“超过几秒算等待”，`--hook` 改“开头算几秒”，`--strict` 在有问题时返回非零退出码，`--json` 输出 JSON。

## 在我自己的视频上

同一条视频的初版和成片。初版因节奏偏慢被修改，成片是修改后的版本：

| 视频 | 版本 | 标出的等待 | 合计 | 占片长 |
|---|---|---|---|---|
| 炎症是什么 | 初版 | 10 段 | 41.0 秒 | 28% |
| 炎症是什么 | 成片 | 1 段 | 4.0 秒 | 3% |
| 南方冷还是北方冷 | 初版 | 16 段 | 58.2 秒 | 44% |
| 南方冷还是北方冷 | 成片 | 10 段 | 35.9 秒 | 26% |

按制作时间排。“每 1.5 到 3 秒一次新东西”这条规则是 10 月 27 日定的：

| 视频 | 做于 | 片长 | 标出的等待 | 占片长 |
|---|---|---|---|---|
| 傅里叶变换 | 10-24 | 2:20 | 15 段 | 44% |
| 地球的夜晚哪里最亮 | 10-26 | 3:11 | 24 段 | 57% |
| 假如你是一滴水 | 10-27 | 2:28 | 0 段 | 0% |
| 假如你是一条消息 | 10-30 | 2:29 | 4 段 | 9% |
| 假如你是一个唐朝普通人 | 11-01 | 2:36 | 2 段 | 4% |
| 慢放一秒 | 11-02 | 1:48 | 4 段 | 15% |
| 假如你是一个汉字 | 11-06 | 2:36 | 1 段 | 2% |
| 南方冷还是北方冷 | 11-08 | 2:16 | 10 段 | 26% |
| 炎症是什么 | 11-08 | 2:16 | 1 段 | 3% |

读这两张表要注意三点：

- 这些是脚本直接输出的数字，未逐段人工复核。脚本存在误报，原因见“局限”。《南方冷还是北方冷》成片的 10 段我让助手逐张看过，确认 3 段，另外 7 段中间其实出现了新标签或新数字。
- 9 条视频都是我一个人做的，同一种风格（字幕加画面，没有口播）。换一种风格，数字不能直接比。
- 我没有拿它和播放量、完播率对比过，数据太少。它只回答“哪里有等待”，不预测留存。

## 它怎么判断“新东西”

1. 每秒取 4 帧，缩到 320×180，把画面切成 16×9 个小块，算每一块和上一帧的差。
2. 某一块的变化远超它周围最近几秒的水平，算一次“新东西”。这样角落里一直在动的东西不会盖住别处新出现的字幕，匀速的移动也不会被当成新内容。
3. 整幅画面在一步之内大面积变化（切镜头、快速运镜、蒙太奇），直接算新内容。
4. 两次“新东西”之间超过 3 秒，标为一段等待，并存下这段时间内部的几帧。

用彩色比较，因为从红切到绿，两边亮度几乎一样，只看灰度会漏掉。

## 局限

- 它比的是像素，看不懂字。移动背景上的字幕切换、慢慢淡入的小元素，变化量不够突出，会被漏掉，结果是多标等待。所以每一段等待都配了图，要看过才算数。
- 它听不到声音。有口播的视频，画面不动的时候可能正在说新内容，这种只能算“画面上的等待”。
- 卡点剪辑和歌词 MV 跟着音乐的拍子走，不适用 1.5 到 3 秒这条规则。
- 阈值是我做这类视频的经验值，不是定律。3 秒可以用 `--max-gap` 改。

## 测试

```bash
python -m pip install pytest
pytest -q
```

测试用 ffmpeg 现场合成几秒钟、答案已知的小视频：纯静止、每 2 秒一次硬切、小块字幕式的变化、只有匀速平移、移动背景上出现字幕、半秒一切的蒙太奇、黑场开头。不依赖任何真实素材。
